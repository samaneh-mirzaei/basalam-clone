# بک‌اند باسلام

[English](README.md)

این پروژه یک API بازارگاه با FastAPI و PostgreSQL است. امکانات پیاده‌سازی‌شده شامل ثبت‌نام، ورود با JWT، پروفایل، فروشگاه، خواندن دسته‌بندی‌ها، محصول و جست‌وجوی SQL، آدرس‌های کاربر، مشاهدهٔ کیف پول و تراکنش‌ها، سبد خرید، محصولات ذخیره‌شده، انتقال بین سبد و ذخیره‌شده، پرداخت با کیف پول و مشاهدهٔ سفارش‌ها است. نقش‌های اپراتور و مدیر همچنان می‌توانند مانند مشتری خرید کنند. عملیات ارسال مرسوله، مرجوعی، بازپرداخت، اصلاح دستی کیف پول و مدیریت دسته‌بندی‌ها و تصاویر هنوز API ندارند.

## پیش‌نیازها

- پایتون ۳٫۱۱ یا جدیدتر و [uv](https://docs.astral.sh/uv/)
- PostgreSQL 18 یا نسخهٔ جدید سازگار، همراه با پایگاه داده‌ای که از قبل ساخته‌اید

## راه‌اندازی محلی

دستورها را در ریشهٔ همین پروژه اجرا کنید:

```powershell
uv sync --locked --extra test
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

پیش از اجرای مهاجرت‌ها، پایگاه دادهٔ PostgreSQL را بسازید. سپس مقادیر واقعی اتصال و یک کلید تصادفی حداقل ۳۲ کاراکتری را در `.env` قرار دهید:

```text
BASALAM_DATABASE_URL=postgresql+psycopg://USERNAME:PASSWORD@127.0.0.1:5432/basalam
BASALAM_JWT_SECRET=YOUR_RANDOM_SECRET_OF_AT_LEAST_32_CHARACTERS
```

نام کاربری، رمز، میزبان، درگاه و نام پایگاه داده را مطابق سیستم خود تغییر دهید. کلید JWT با رمز PostgreSQL فرق دارد. کاراکترهای ویژهٔ نام کاربری یا رمز را در URL به‌صورت percent-encoding بنویسید. مقادیر `.env.example` نمونه و غیرقابل‌استفاده‌اند؛ `.env` را در Git ثبت نکنید.

```powershell
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

برای آزمایش دستی، [Swagger UI](http://127.0.0.1:8000/docs) را باز کنید. ابتدا با `POST /api/v1/auth/tokens` و شمارهٔ موبایل و رمز حساب وارد شوید. مقدار `data.access_token` را بردارید و **فقط خود توکن** را در بخش **Authorize** قرار دهید. مسیر `GET /health` فقط پاسخ‌گویی برنامه را بررسی می‌کند و اتصال پایگاه داده را نمی‌سنجد. Alembic جدول‌ها، enumها، کلیدهای خارجی، نمایه‌ها و محدودیت‌ها را در پایگاه دادهٔ موجود می‌سازد. مهاجرت‌های `0003_address_phone_length`، `0004_payment_debit_required` و `0005_admin_role` ساختار را بدون پاک‌کردن حساب‌ها گسترش می‌دهند. برای اجرای مهاجرت‌ها به فایل‌های اولیهٔ DBML و SQL طراحی نیازی نیست.

## نقش‌ها و مدیریت دسترسی

سه نقش `customer`، `operator` و `admin` وجود دارد. هر سه نقش به کیف پول، سبد، آدرس‌ها و خرید خود دسترسی دارند. اپراتور و مدیر می‌توانند وضعیت فروشگاه‌ها را بررسی کنند و از کنترل‌های عملیاتی فروشگاه استفاده کنند؛ مدیر طبق دسترسی اپراتور می‌تواند رسید سفارش‌ها را نیز ببیند. تنها مدیر می‌تواند با `GET` و `PATCH /api/v1/admin/users/{user_id}` نقش یا وضعیت فعال‌بودن حساب‌ها را مشاهده یا تغییر دهد. برای PATCH باید `Content-Type: application/merge-patch+json` ارسال شود. مدیر نمی‌تواند دسترسی مدیریتی خودش یا آخرین مدیر فعال را حذف کند. این مسیرها رمز، موجودی کیف پول یا سبد را تغییر نمی‌دهند.

ثبت‌نام عمومی همیشه حساب `customer` می‌سازد. اسکریپت دادهٔ نمایشی در ادامه یک مدیر نمایشی ایجاد می‌کند. برای ارتقای یک حساب موجود دیگر در پایگاه دادهٔ محلی `basalam`، پس از اجرای مهاجرت‌ها از دستور زیر استفاده کنید:

```powershell
uv run python scripts/promote_admin.py --mobile 09XXXXXXXXX --confirm
```

این دستور رمز، کیف پول، تراکنش‌ها و سبد حساب را تغییر نمی‌دهد. دسترسی به پایگاه دادهٔ محلی و فایل `.demo-credentials` را خصوصی نگه دارید. حساب‌های نمایشی اپراتور و مدیر هر دو می‌توانند خرید کنند.

## آزمایش خرید در Swagger

یک خریدار و یک فروشنده ثبت و احراز هویت کنید. فروشنده یک فروشگاه و محصول منتشرشده بسازد. خریدار یک آدرس بسازد، محصول را به سبد اضافه کند و `GET /api/v1/users/me/cart` را بخواند. سپس مقدار `displayed_total` سبد، شناسهٔ آدرس **به‌شکل رشته** و یک `checkout_key` تازه را به `POST /api/v1/orders` بفرستد. هنگام پرداخت، موجودی انبار، وضعیت محصول و فروشگاه، قیمت و موجودی کیف پول دوباره بررسی می‌شوند. تکرار همان کلید با همان درخواست، رسید قبلی را برمی‌گرداند؛ تغییر درخواست با همان کلید خطای 409 می‌دهد. خریدار سفارش‌ها را از `GET /api/v1/users/me/orders` و جزئیات را از `GET /api/v1/orders/{order_id}` می‌بیند.

هر نصب تازه به پایگاه داده و `.env` مخصوص خودش نیاز دارد؛ فایل‌های پایگاه داده و رمزهای محلی در Git قرار نمی‌گیرند.

## دادهٔ نمایشی

`uv run python scripts/seed_demo.py` فقط وقتی کار می‌کند که پایگاه دادهٔ تنظیم‌شده محلی و نام آن `basalam` باشد. ابتدا مهاجرت‌ها را اجرا کنید. این دستور یک خریدار، فروشنده، اپراتور، **مدیر**، فروشگاه، دو دسته‌بندی و چهار محصول می‌سازد. هر حساب نمایشی تازه یک کیف پول، یک اعتبار اولیهٔ ۱٬۰۰۰٬۰۰۰ تومانی و سبد خالی دریافت می‌کند. اجرای دوبارهٔ آن رمز حساب‌های موجود را عوض نمی‌کند و اعتبار اولیهٔ تکراری نمی‌دهد. رمز مشترک و شماره‌های موبایل در فایل خارج از Git به نام `.demo-credentials` نوشته می‌شوند؛ آن را با `Get-Content .demo-credentials` بخوانید. اگر قبلاً دادهٔ نمایشی ساخته شده باشد، اجرای دوباره حساب مدیر را اضافه می‌کند و شمارهٔ او را به فایل رمز موجود می‌افزاید. سه محصول عمومی‌اند؛ محصول پیش‌نویس فقط برای مالک، اپراتور یا مدیر قابل‌مشاهده است. اگر حساب‌های نمایشی وجود داشته باشند اما فایل رمز حذف شده باشد، اسکریپت از بازنشانی رمز آن‌ها خودداری می‌کند.

## آزمون‌ها

```powershell
uv run --locked --extra test pytest -q
```

آزمون‌های یکپارچه‌سازی PostgreSQL داده می‌نویسند و فقط وقتی **هر دو** متغیر محیطی `BASALAM_DATABASE_URL` و `BASALAM_JWT_SECRET` تنظیم شده باشند اجرا می‌شوند؛ وجود مقدار در `.env` به‌تنهایی آن‌ها را فعال نمی‌کند. آن‌ها را به یک پایگاه دادهٔ **جداگانه، موقت و مهاجرت‌داده‌شده** متصل کنید، نه پایگاه دادهٔ توسعه یا مشترک. آزمون‌ها دسترسی نقش‌ها، حساب نمایشی، انتقال محصول، بازگشت تراکنش ناموفق، تکرار پرداخت، رقابت بر سر موجودی انبار و کیف پول و مالکیت سفارش را پوشش می‌دهند. پس از ساخت پایگاه دادهٔ موقت، برای نمونه:

```powershell
$env:BASALAM_DATABASE_URL = 'postgresql+psycopg://USERNAME:PASSWORD@127.0.0.1:5432/basalam_test'
$env:BASALAM_JWT_SECRET = 'a-test-only-secret-with-at-least-32-characters'
uv run --locked alembic upgrade head
uv run --locked --extra test pytest -q
```

پیش از استفادهٔ دوباره از پایگاه دادهٔ توسعه، این دو متغیر محیطی را از همان نشست ترمینال پاک کنید.
